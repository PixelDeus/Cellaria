## Часть 1: Теорема композиции

### Постановка

Пусть имеются два набора правил R₁ и R₂, каждый из которых является conflict-free
(то есть граф конфликтов внутри каждого набора пуст). Образуем объединение
R = R₁ ∪ R₂ и построим его конфликт-граф.

Если конфликт-граф объединения пуст, то:

1. Все свойства R₁ сохраняются: правила из R₁ срабатывают так же, как при
   изолированном запуске.
2. Все свойства R₂ сохраняются: правила из R₂ срабатывают так же, как при
   изолированном запуске.
3. Арбитраж для объединённого набора правил можно безопасно пропустить.

### Доказательство

**Определение conflict-free.** Набор правил называется conflict-free, если его
конфликт-граф пуст. Конфликт-граф пуст, когда для любой пары правил из набора
их *affected regions* (области влияния) не пересекаются ни при каких позициях
совпадения на решётке.

**Шаг 1.** R₁ conflict-free ⇒ для любых i, j ∈ R₁: affected(i) ∩ affected(j) = ∅.
**Шаг 2.** R₂ conflict-free ⇒ для любых i, j ∈ R₂: affected(i) ∩ affected(j) = ∅.
**Шаг 3.** Конфликт-граф для R₁ ∪ R₂ пуст ⇒ для любых i ∈ R₁, j ∈ R₂:
affected(i) ∩ affected(j) = ∅.

**Шаг 4.** Из шагов 1–3 следует, что все affected regions в объединении попарно не
пересекаются. Это означает, что ни одно правило не конкурирует с другим за
запись в одни и те же ячейки.

**Шаг 5.** Поскольку ни одно правило не конкурирует за ячейки, результат
применения набора R₁ ∪ R₂ эквивалентен последовательному или параллельному
применению правил из R₁ и R₂ в любом порядке. Следовательно, арбитраж не
требуется — все совпадения можно применить одновременно.

**Шаг 6.** Правила из R₁ при объединении с R₂ ведут себя идентично изолированному
запуску, так как R₂ не может изменить ячейки, которые R₁ читает или пишет.
Аналогично для R₂. ∎

## Часть 2: Каталог сохраняющих операций

Ниже перечислены операции над набором правил, которые гарантированно сохраняют
свойство conflict-free.

### 2.1 Добавление правила с уникальным head-типом

**Утверждение.** Если новое правило имеет head-тип, не встречающийся ни в одном
существующем правиле, то объединённый набор остаётся conflict-free.

**Доказательство.** Правила с разными head-типами (первый элемент id) не могут
совпасть на одной и той же ячейке одновременно, так как тип этой ячейки должен
быть одновременно равен обоим head-типам, что невозможно. Следовательно,
affected regions не пересекаются. ∎

### 2.2 Добавление правила с изолированным min_age

**Утверждение.** Если min_age нового правила строго больше максимального возраста
любой ячейки, участвующей в существующих правилах, то объединённый набор
остаётся conflict-free.

**Доказательство.** Новое правило активируется только в момент времени
t ≥ min_age. Существующие правила активируются в t < min_age. Их временные окна
не пересекаются — они не могут совпасть одновременно. ∎

> **Замечание.** В текущей реализации возраст ячейки измеряется в тиках с момента
> последнего изменения. Максимальный возраст, при котором правило может
> активироваться, равен min_age − 1 для правил с min_age > 0, и не ограничен
> для правил с min_age = 0.

### 2.3 Пространственная изоляция

**Утверждение.** Если все affected regions нового правила находятся на расстоянии
> K от всех affected regions существующих правил (где K — максимальный размер
цепочки среди всех правил), то объединённый набор остаётся conflict-free.

**Доказательство.** Affected regions определяются относительно позиции совпадения
правила. Два правила могут сработать в разных местах решётки. Если между этими
местами расстояние больше K, то их affected regions не могут пересечься при
любых сдвигах, так как affected regions по построению не выходят за пределы
цепочек длины K. ∎

### 2.4 Композиция через непересекающиеся типы

**Утверждение.** Если множества типов, используемых в R₁ и R₂, не пересекаются,
то конфликт-граф объединения пуст.

**Доказательство.** Это следствие Lemma 1 из Статьи 2: если два правила не имеют
общих типов, они не могут совпасть одновременно (ни одна ячейка не может иметь
два разных типа). Следовательно, их affected regions не пересекаются. ∎

## Часть 3: Демонстрационный конфиг — TM-головка + очистка

Файл: `configs/composition.yaml`

### R₁: TM-головка (конфликт-фри)

| id | Head-тип | Сдвиг    | min_age | Описание |
|----|----------|----------|---------|----------|
| [10] | 10 | east 1 | 0 | Состояние A, читает бит, пишет 0, сдвиг вправо |
| [1]  | 1  | —      | 0 | Символ "0" на ленте |
| [2]  | 2  | —      | 0 | Символ "1" на ленте |

Все три правила имеют разные id (первые элементы: 10, 1, 2), поэтому их affected
regions не пересекаются → R₁ conflict-free.

### R₂: Правило очистки (конфликт-фри)

| id | Head-тип | Сдвиг | min_age | Описание |
|----|----------|-------|---------|----------|
| [99] | 99 | —    | 5 | Маркер очистки, удаляет отработанные символы через 5 тиков |

R₂ состоит из одного правила → conflict-free тривиально.

### R₁ ∪ R₂: Проверка композиции

- **Head-типы:** R₁ использует {10, 1, 2}, R₂ использует {99} — не пересекаются.
- **min_age:** R₁ имеет min_age ∈ {0}, R₂ имеет min_age = 5 — разные.

По критериям 2.1 и 2.2: конфликт-граф объединения пуст → композиция безопасна.

**Ожидаемое поведение при симуляции:**
1. Головка (тип 10) движется слева направо по ленте, инвертируя биты.
2. После прохода головки остаются ячейки с типом 0 (fill).
3. Через 5 тиков после активации правила очистки (тип 99) мусорные маркеры
   удаляются.
4. TM-головка и очистка не конкурируют за ячейки — арбитраж не нужен.

## Часть 4: Реализация и тесты

### `CompositionVerdict`

```rust
/// Результат проверки композиции двух conflict-free наборов правил.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum CompositionVerdict {
    /// Все правила можно применять одновременно, арбитраж не нужен.
    Safe,
    /// Найдены конфликты с указанием пар индексов (i-из-R₁, j-из-R₂).
    Unsafe(Vec<(usize, usize)>),
}
```

### `ConflictGraph::check_composition`

```rust
pub fn check_composition(rules_a: &[Rule], rules_b: &[Rule]) -> CompositionVerdict {
    let mut combined = rules_a.to_vec();
    combined.extend_from_slice(rules_b);
    let graph = Self::build(&combined);
    if graph.is_conflict_free() {
        CompositionVerdict::Safe
    } else {
        // Преобразование глобальных индексов в пары (i∈R₁, j∈R₂)
        let n_a = rules_a.len();
        let unsafe_pairs: Vec<(usize, usize)> = graph
            .edges
            .iter()
            .filter_map(|&(i, j)| {
                if i < n_a && j >= n_a { Some((i, j - n_a)) }
                else if i >= n_a && j < n_a { Some((j, i - n_a)) }
                else { None }
            })
            .collect();
        CompositionVerdict::Unsafe(unsafe_pairs)
    }
}
```
